# UI 规则（RULE）· City 与仪表的结构规矩

议题：ISSUE-9（City / 仪表的结构规矩），状态 rule。领域主人：箭10（UI 游戏化）。草稿起草：UI / World，2026-11-25。

依据 LAW-1 第九条：RULE 用来执行 LAW，由领域主人定和维护，不进法的名录。每条 RULE 都写明它执行哪条法。

本页挂的法只有下面四条（引用以名录为准）：

- **LAW-8 二**：数从源头现算，不靠手维护。
- **LAW-8 四**：游戏化界面是人和 Agent 一起做事的具象化。表现和系统分开；只读系统存档，真实反映，反映不了的不假装；City 是感知系统的入口，也是边界；街区按领域分，菜单按功能分。
- **ZONE-1 五**：页面只放数据和图，解读收进「?」，按业务问题排主次。
- **ZONE-2**：视图只接 UI 引擎。

每条规则后面写三样：

- **执行**：它执行哪条法。
- **守法**：怎么检查。「机器」是代码里的检查或测试，写明在哪里；「人眼」是走查时看。
- **在哪**：实现在哪里。

规则里不写谁在哪天说过什么；来历查议题簿（Console → Command → Owner's issues，ISSUE-9）。

## 一、地面与尺寸

**RULE-UI-1 · 一张地 16×16，最多 16 样东西。** 每一层（城、街区、楼）的地面都是同一张 16×16 的格子。一张地上最多放 16 样东西，所占的格子加起来不超过 256。
- 执行：LAW-8 四（万物分档）
- 守法：机器，`city/rules.ts` 的 `rulesBroken`（每一层、每一张地都查）。违反规则的那一处空着不画，并写明原因（`containBroken`）。
- 在哪：`city/grid.ts`（`GRID`、`MAX_THINGS`）

**RULE-UI-2 · 尺寸按分量定，只有固定的几种。** 最小单位是 4×4。街区和楼分小、中、大三档：4×4、4×8、8×8。尺寸表示这样东西的分量，不表示里面装了多少。不出现其他尺寸。
- 执行：LAW-8 四（万物分档）
- 守法：机器，`rulesBroken`（形状、最小单位、能点进去的至少一格宽）
- 在哪：`city/grid.ts`（`SHAPES`、`CLASSES`、`UNIT`）

**RULE-UI-3 · 一个街区有 1、2 或 4 张地。** 街区占多大，取决于它在城市层分到的地：4×4 是 1 张，4×8 是 2 张，8×8 是 4 张。每一张地单独按 RULE-UI-1 检查。东西多到所有地都放不下时，多出来的进同一块「Other」工地，工地上写明里面是哪几样，不丢、不藏。
- 执行：LAW-8 四（反映不了的不假装）
- 守法：机器，`rulesBroken` 按张检查（`places.ts` 的 `sheetsOf`）。内容一侧有测试守着：例如硬件街区按设备数分张、放不下的进 Other。
- 在哪：`city/places.ts`（`sheetCount`、`sheetsOf`、`onSheet`）

**RULE-UI-4 · 先有地，后有楼。** 地块由人来切、合、转。楼只能放进已经放得下它的地块；放不下的标红，不让放。地上已经有楼时，不能切、转、合，会挪动或改变有楼的地的按钮也不出现。
- 执行：LAW-8 四（人只做人该做的）
- 守法：机器，`grid.ts` 的切、合、转函数和 `leavesBuiltLand`
- 在哪：`city/grid.ts`、`CityGen2.tsx`（Arrange）

**RULE-UI-5 · 每一层汇总下一层。** 外面的一格对应里面的一张地，细节要进去才看得到。
- 执行：ZONE-1 五（主次有序）
- 守法：人眼
- 在哪：`city/placeScene.ts`

## 二、真实与读数

**RULE-UI-6 · 画面上的每样东西都有真实来源。** 每栋楼、每个房间、每个数、每种状态、每个动态效果，背后都是系统里真实存在、读得到的东西。实体清单从权威源读（拓扑、监控、路由表、领域归属表），不在内容里手写。
- 执行：LAW-8 二、LAW-8 四（只读系统存档）
- 守法：机器，`rulesBroken` 要求读数写明来源（`READ_SOURCE`），内容一侧有「整棵树来自读口」的测试；人眼，走查时核对每个数的来源
- 在哪：`city/rules.ts`；各领域的内容翻译层

**RULE-UI-7 · 读不到就是「未读」，不是 0。** 读数必须写明来源，不能是负数，用量不超过总量。读不到的写「未读」并说明原因，不写数字，也不写 0。没接上的东西画成透明、虚线，一眼分得出哪些还不存在。
- 执行：LAW-8 四（反映不了的不假装）
- 守法：机器，`rulesBroken`（meter 那几条）；人眼
- 在哪：`city/rules.ts`、`city/cityGen2.css`

**RULE-UI-8 · 状态只用七个词，颜色就是严重度。** 只有 ok、warn、fail、boundary、unknown、pending、info 七个词，颜色只从 `STATUS` 表里取。超过声明的新鲜期一律算 fail。正在干活、在等人写 info。不是故障、按自己节奏、还没轮到的写 boundary。unknown 只给读失败或来源不可用的情况，并写明是哪一路。pending 只表示读还没回来，永远不算一条发现。一个汇总灯取它下面最严重的那一项，顺序是 fail > warn > unknown > info > boundary > ok。
- 执行：LAW-8 四（真实反映）、ZONE-1 五
- 守法：机器，`world.ts` 的 `STATUS_WORDS` 是封闭的词表，各视图的映射表都映射到它；人眼，走查时查有没有自己配的颜色
- 在哪：`city/world.ts`

**RULE-UI-9 · 同一件事只有一个数。** 告警数、等 Owner 处理的数、各条线的 merged / STG / PROD 计数，在每个视图里都用同一个函数算出同一个数，并且读不到时都写「?」。
- 执行：LAW-8 二
- 守法：机器，各视图共用同一个计数函数，有测试；人眼，走查时把两处并排对一下
- 在哪：`city/alerts.ts`；外框的等待标签（`WorldFrame` 的 `waiting`）

## 三、拟物

**RULE-UI-10 · 一个比喻只代表一样东西，按对照表画。** 指标画成什么拟物，以对照表为准。同一种东西全城只有一种画法；一个比喻只代表一样东西，例如一台计算机画成一座工厂，存储画成仓库。不画机器本身的样子。
- 执行：LAW-8 四（表现和系统分开）
- 守法：机器，对照表是数据，每个设施的画法都要查表；图例的行正好是画法用到的行（测试）
- 在哪：`city/library/dictionary.ts`、`city/library/key.ts`

**RULE-UI-11 · 容量用标准件来数。** 每种资源有一个固定大小的标准件，全城统一、对齐。容量画成几个标准件，大的看起来就大，不同机器之间一眼能比。
- 执行：LAW-8 四（万物分档）
- 守法：机器，标准件的大小在对照表里；人眼
- 在哪：`city/library/dictionary.ts`、`city/units/*`

**RULE-UI-12 · 硬件只显示它本身。** 硬件的房间里只放硬件层面的东西：有多少、用了多少、各部分的状态。哪个服务跑在它上面属于关系层，不画在房间里。房间只显示此刻；历史放在外面。
- 执行：LAW-8 四（真实反映）
- 守法：人眼；户型固定（CPU、内存、磁盘的顺序）由内容一侧的规则检查
- 在哪：`city/units/*`、`city/units/standards.ts`

**RULE-UI-13 · 房间按房间标准做。** 每个房间都按 `units/standards.ts` 里的条目设计：有控制台、东西不互相挡、没有多余的部件、一眼看清，并且每条标准写明怎么检查（测试或人眼）。新房间先按标准走查，再进城。
- 执行：LAW-8 四、ZONE-1 五
- 守法：标准表本身是数据，每条标注 `check: 'test' | 'eye'`
- 在哪：`city/units/standards.ts`

## 四、组织与交互

**RULE-UI-14 · 街区按领域分，菜单按功能分。** 城里的街区就是领域归属表里的领域；底部菜单是 Console 的功能。两个维度分开显示：菜单点亮的是为该功能服务的那些地方，不重排街区。
- 执行：LAW-8 四（街区按领域，菜单按功能）
- 守法：机器，内容一侧从领域读口生成街区（不手写），菜单从 Console 路由生成
- 在哪：`city/places.ts`（`function`）、`CityGen2.tsx`

**RULE-UI-15 · 实体归内容，连接归框架。** 楼和房间由内容给；马路、楼道、口子的样式由框架统一，内容画不了也改不了。每边最多 3 个具名口子，留给最常打交道的伙伴，其余进 Other；没声明的画成「未声明」。连接的方式只有两种（总线和指标），用车的种类区分。
- 执行：LAW-8 四（表现和系统分开）、ZONE-2
- 守法：机器，`links.ts` 的 `linkRulesBroken`、`edgeSlots`
- 在哪：`city/links.ts`、`city/traffic.ts`

**RULE-UI-16 · 名牌一行，默认不显示。** 名牌只占一行，最多 18 个字符，名牌之间不互相压。楼的外形说明它是什么，编号说明它是哪一台。名牌的显示方式只有三种：不透明、半透明、隐藏，按观看的人分别记住。
- 执行：ZONE-1 五（只放数据和图）
- 守法：机器，`labels.ts` 有字数上限和避让
- 在哪：`city/labels.ts`

**RULE-UI-17 · 进出要连得上，位置要能找回。** 从一个地方进到另一个地方，看起来像放大和缩小，不是跳转。小地方保持真实比例，不放大铺满屏幕。缩略图标出你在哪里。每个地方都有地址，可以直接打开，也能返回。City 和 Console 是同一个地方的两种看法，能来回切换，切过去仍落在同一个东西上。
- 执行：LAW-8 四
- 守法：机器，地址的读写有测试（`#city?at=…&sel=…`），返回轨迹有测试；人眼
- 在哪：`city/placeScene.ts`、`city/WorldFrame.tsx`

**RULE-UI-18 · 卡片是一眼看的，中间是干活的。** 卡片只放数据和图，说明收进「?」。卡片由引擎画，内容只交数据（表格、事实、注释），不写标记。同一套外框、同一套部件，各视图统一语言，但不统一画风：场景和仪表两种画面共用同一套状态词和颜色。
- 执行：ZONE-1 五、ZONE-2
- 守法：机器，卡片是数据（`city/cards.ts`），内容写不了标记；人眼，在 390 和 1280 两个宽度走查
- 在哪：`city/cards.ts`、`city/parts.tsx`、`city/WorldFrame.tsx`

**RULE-UI-19 · 信号的中控大屏用灯组。** 仪表的第一屏是一块大屏：一个模块一组灯，一种状态一盏灯，红的一眼就能看到；需要注意的（fail、warn）计数放在标题上，「读不到」单独一行，boundary 不出声。
- 执行：LAW-8 四、ZONE-1 五
- 守法：机器，控制室模型有测试；人眼
- 在哪：`observation/ControlRoom.tsx`、`observation/model.ts`

## 怎么改这一页

- 改 RULE 由领域主人定，写明执行哪条法。
- 找不到可挂的法的 RULE，按 LAW-1 第九条处理：要么补立法，要么删掉这条。
- 改裁判类的 RULE（例如 `rulesBroken` 的判定条件）照 LAW-9 交 Owner 定。
- 本页和代码对不上时，以代码和测试为准，并改这一页。
